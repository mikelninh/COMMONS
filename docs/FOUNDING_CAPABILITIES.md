# Founding Capabilities Pilot

Goal: learn how real people, businesses and agents describe useful capability before
opening a public marketplace.

## Pilot size

Start with 5-10 invited providers across different supply types:

- person
- business
- nonprofit/community organisation
- AI agent/tool
- physical or compute resource

Do not ask them to design a schema. COMMONS interviews them and proposes the
capability card for approval.

## Capability interview

Ask in ordinary language:

1. What do people reliably come to you for help with?
2. What kinds of problems do you enjoy or want to help solve?
3. What would you need from someone before you can help?
4. What can you actually deliver, and how would we know it was done?
5. Where, when and in which languages are you available?
6. Is this free, paid, sponsored, or dependent on the case?
7. What should you never be asked to do without explicit approval or credentials?
8. Which parts could an AI/tool do, and where is human judgment or presence important?
9. What evidence could support this capability: credentials, examples, references,
   completed tasks, API docs, transaction receipts, or future observed outcomes?

## COMMONS-generated capability card

COMMONS proposes:

- provider kind
- capability type
- description
- accepted inputs
- outputs
- location
- languages
- availability/capacity
- price or funding model
- authority ceiling
- verification status
- verification method
- provider preferences
- historical outcomes

The provider reviews and approves the card before it becomes active.

## Human-preserving rule

COMMONS does not treat humans as expensive versions of agents.

The planner distinguishes:
- tasks where automation is appropriate;
- tasks where a human is preferred;
- tasks where a human is required;
- hybrid tasks such as AI draft + human review.

Default planning is best fit within budget. Cost-only optimization is an explicit
experiment, never the default.

## Pilot learning

For each onboarding, record:
- time to create a useful capability card;
- whether the person recognizes themselves in it;
- missing fields;
- trust/authority concerns;
- whether they would accept a real matched task;
- whether the capability was later matched;
- outcome quality after a match.

The first milestone is not provider count. It is five capability cards that real
people say are accurate enough that they would accept or reject work through them.
